
# Phase 8: Centralized Logging

## Overview
TaskFlow uses the ELK Stack (Elasticsearch, Logstash, and Kibana) with Fluent Bit for centralized log collection, storage, processing, and visualization.

## Log Sources
1. Application logs: Structured JSONL logs generated by the Flask application.
2. Docker logs: Container logs collected from Docker JSON log files.
3. Kubernetes logs: Continuously collected from Kubernetes container log files using Fluent Bit DaemonSet.

## Architecture
- Logstash reads application and Docker log files.
- Logstash processes events and forwards them to Elasticsearch.
- Fluent Bit runs as a Kubernetes DaemonSet and tails `/var/log/containers/*.log`.
- Fluent Bit enriches records with Kubernetes pod and container metadata.
- Fluent Bit forwards Kubernetes logs to Elasticsearch over HTTP.
- Elasticsearch stores the logs in daily indices.
- Kibana provides searchable log views and filtering.

## Kubernetes Log Collection
- Namespace: `logging`
- Collector: Fluent Bit 3.2.10
- Deployment type: DaemonSet
- Input: Tail plugin with CRI parser
- Metadata enrichment: Kubernetes filter
- Output: Elasticsearch output plugin
- Elasticsearch endpoint: `host.minikube.internal:9200`
- Index prefix: `taskflow-k8s`
- Daily index format: `taskflow-k8s-YYYY.MM.DD`
- Kubernetes labels and annotations are disabled to avoid Elasticsearch mapping conflicts.
- Fluent Bit uses a persistent host-mounted database for tail input state.

## Elasticsearch
Application and Docker index pattern: `taskflow-logs-*`

Kubernetes index pattern: `taskflow-k8s-*`

Source types:
- application
- docker_container
- kubernetes_pod
